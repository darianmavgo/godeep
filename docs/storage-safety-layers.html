Storage Safety Layers: Bare Metal to OS Concept

Comparison across Apple macOS/iBoot, Asahi Linux, Go Standard Library, and TamaGo (ARM64)

Safety LayerHardware → OS Abstraction Apple Stack SolutioniBoot / XNU / DriverKit Asahi Linux Solutionm1n1 / Linux Kernel (C & Rust) Go Std LibraryUserspace Runtime & Packages TamaGo SolutionBare-Metal Go Unikernel
1. Silicon Boundary IOMMU / DMA Safety Restricts physical RAM access from NVMe / ANS2 controllers. Native Hardware + XNU
AppleSART & AppleDART drivers in XNU program hardware page tables and physical address filters before AppleANS2NVMeController issues DMA. 		Native Kernel Drivers
apple-sart.c & apple-dart.c bind via the Linux iommu subsystem, isolating DMA bounce buffers per device. 		Not Applicable
Userspace runtime has no visibility into physical addresses, IOMMUs, or DMA engines; relies on host OS syscalls. 		DMA Allocator Only
tamago/dma allocates contiguous uncached/aligned buffers, but contains no Apple DART or SART IOMMU drivers (must be supplied by godeep).
2. Raw Device Layer Block Safety Enforces sector alignment, device LBA limits, and queue integrity. IOKit Storage Family
IOBlockStorageDriver & IONVMeController enforce 4 KB block alignment, command timeouts, and device max-LBA bounds. 		Linux Block Layer
nvme-apple.c (RTKit + ANS2) feeds blk-mq; bio_check_eod() rejects out-of-range sectors and unaligned requests. 		Interface Only
io.ReaderAt / io.WriterAt pass byte offsets; no built-in sector alignment or hardware block queue enforcement. 		Minimal / Board-Specific
Provides basic SD/MMC helpers on select SoCs, but has no NVMe, PCIe, or Apple ANS2/RTKit block driver.
3. Multi-OS Boundary Partition Safety Fences LBA ranges so neighboring OSes cannot be overwritten. IOGUIDPartitionScheme
Parses GPT headers/CRC32s, creates bounded IOMedia child objects per slice, and hides system/recovery containers from casual writes. 		Kernel Partition Parser
block/partitions/efi.c validates primary/backup GPT CRC32s, rejects overlapping LBAs, and maps part->bd_start_sect offsets. 		No Native Parser
No GPT or MBR parser in stdlib. Would be built using Go slice bounds-checking concepts over a custom block interface. 		None
TamaGo targets single-purpose unikernels/payloads and omits disk partition table parsing entirely.
4. Storage Abstraction Volume Safety Manages logical volumes, read-only flags, and container pooling. APFS Container / CoreStorage
APFS dynamically shares space across volumes inside one partition with copy-on-write snapshots, volume roles, and read-only system seals (SSV). 		Device Mapper / Btrfs / LVM
dm-crypt, dm-verity, or Btrfs subvolumes enforce read-only mounts, block-level checksums, and logical volume isolation. 		Abstract Interfaces
io/fs.FS provides read-only filesystem abstraction by design, but lacks block-level volume pooling or device-mapper semantics. 		None
No logical volume manager or block device abstraction layer.
5. OS Data Integrity File System Safety Protects metadata, journals, inodes, and directory trees. APFS / HFS+ VFS
Copy-on-write metadata trees, atomic safe-save transactions, hardware-accelerated AES-XTS file encryption, and VFS sandbox enforcement. 		Linux VFS (ext4 / APFS / FAT)
ext4 journaling (JBD2), fs/fat, and VFS path resolution (`openat2`) prevent directory traversal and recover cleanly after power loss. 		Path & Read Safety
os.Root (Go 1.24+) blocks directory traversal; io/fs is read-only. Contains no on-disk filesystem driver (no FAT32/ext4). 		None
Relies on Go's in-memory embed.FS or external libraries; no native on-disk FAT32 or ext4 driver.
